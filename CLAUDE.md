# Piano Learning Path

A personal piano practice web app (React, built with Vite, hosted on GitHub Pages), used on a Mac, an iPad and an iPhone.

## About me (the pianist)

- Level: late beginner / early intermediate.
- Repertoire I play: Chopin Waltz in A minor, B. 150. Still learning: Chopin Waltz in B minor, Op. 69 No. 2 (stage item `s1r0`; it joins Keep up once checked).
- Scales: all major scales and their relative natural minors, hands together, at 95 bpm.
- Not yet learned: harmonic and melodic minor.
- Russian arpeggio set (11 forms per key): solid in C, G, D, A, E, B. Still to learn: F, F#, Db, Ab, Eb, Bb.
- Chords: learning the diatonic triads and 7th chords of every major key and its relative minor in all inversions, plus cadences (own rotation, one a day: a major key, then its relative minor the next day).
- Practice is item based, not timed: a daily set of items to tick, no minutes.
- Taste: mainly Chopin and Romantic repertoire, with Bach for finger independence.

When suggesting repertoire, use real pieces with correct catalogue numbers (Op., B., BWV, D.), and keep each stage a realistic step up from the one before.

## How the site is built

Vite + React 19 + TypeScript. Node 22 (`.nvmrc`). On this Mac `npm start` runs `nvm use` and then the dev server; `npm run dev` alone runs the local server (also reachable from the iPad/iPhone on the same Wi-Fi), `npm run build` to typecheck and build into `dist/`.

- `src/data/curriculum.ts`: `KEYS`, `STAGES`, `MAINTAIN`. Each stage item has `id`, `c` (T = technique, E = étude, R = repertoire, H = theory), `t` (title), optional `d` (practice tip), optional `q` (exact IMSLP page title, e.g. "Preludes, Op.28 (Chopin, Frédéric)"; IMSLP search URLs land on a bot check, so link pages, not searches). Sight-reading was dropped (Today block and the stage items `s1s1`–`s4s1`; don't reuse those ids). Repertoire items can have `keep` (the title shown in Keep up once finished).
- Pieces: each repertoire item has a learning step (`PIECE_STEPS` in `curriculum.ts`, 5 steps) and an optional "working on bars" note, in state `pieces`. Reaching the last step checks the item; going back un-checks it. Today's New piece tip follows the step. Keep up rotates (one a day) through `MAINTAIN` plus every checked repertoire item (`maintained()`).
- **Never rename or reuse an item `id`**: saved progress is keyed by id. Add new ids instead.
- `src/state/store.ts`: the single app state, `useAppState()` hook, `update(fn)` for changes, `replaceState()` for sync. `src/state/actions.ts`: every state change goes through here.
- State shape: `{settings:{minutes,stage}, arps:{C:"solid"|"learning"|"none",...}, scales:{C:{maj,nat,harm,mel}}, checks:{id:true}, fingerings:{"A:3":"..."}, pieces:{id:{step,bars?}}, log:[{d,n?,note,items,ts,auto?}] (old entries have `min` instead of `n`), logDeleted:[ts], today, rot, study:{miss,days}, analysis:{<piece>:[{id,bars,key,harm,note}]}, updatedAt}`. New fields must be optional in `normalize()` so older saved copies still load.
- Saving: always `localStorage` key `pianoPath.v1` first. Metronome tempo, beats and sound (`woodblock` / `beep` / `windup`, `metroTick()` in `src/lib/audio.ts`) are kept separately in `pianoPath.metronome` (not synced).
- UI choices are remembered per device (not synced) with `usePref()` / `useDayPref()` in `src/lib/prefs.ts`; any new tab, toggle or open/closed section should use them too. Kept: `pianoPath.arpTab` (Forms/Fingering), `pianoPath.chordView` (Triads/7ths/Cadences), `pianoPath.chordPos` (inversion or starting position, one per chord type), `pianoPath.chordMode` (Technique's major/minor), `pianoPath.chordNotation` (Letters/Staff), `pianoPath.chordClef` (Treble/Bass for triads and 7ths on the staff),  `pianoPath.collapsed` (folded Today blocks), `pianoPath.pathOpen` (open stages on Path), Study's `pianoPath.studyChordKey`, `pianoPath.ksAsk`, `pianoPath.ksClef`, `pianoPath.ccKey` / `ccMode` / `ccType` / `ccLayout` (chord flashcards), `pianoPath.rdKey` / `rdMode` / `rdLevel` / `rdMeter` (reading passages), `pianoPath.d7Sig`, `pianoPath.sdKey` / `sdMode` / `sdKind`, `pianoPath.ctKey` / `ctMode` (harmony drills), `pianoPath.anPiece` (analysis notes). For today only, then back to the suggested key: `pianoPath.formKey` and `pianoPath.chordKey` (Technique's key pickers).
- Sync (`src/state/sync.ts`): one private GitHub Gist with file `piano-path.json`, found by filename or created on first connect. The token (classic, `gist` scope) is pasted per device in the sync sheet and kept in `localStorage` key `pianoPath.gist`; never put it in code. Merge rule: `log` is the union by `ts` minus `logDeleted`; everything else comes from the copy with the newer `updatedAt`. Syncs on start, after a local change (2 s after the first, then at most one write a minute while editing: `PUSH_GAP_MS`; leaving the app or Sync now sends right away); while a change waits the status is `pending` ("Saved here · syncing soon", steady dot), on return to the app, on reconnect, and every 2 min while visible. Reads send the last ETag (`If-None-Match`, `lastRead` holds the ETag + file text, also taken from a write's reply); an unchanged gist answers 304, which GitHub doesn't count toward the 5,000/hour limit shared by every app on the account.
- `src/lib/arpeggios.ts`: the 11 Russian arpeggio forms as intervals; notes are spelled by letter + semitones (correct ♯/♭/𝄫), with `enharmonic()` for unusual spellings. `arpFingering()` gives each form one octave of notes with standard RH/LH fingering from rules (thumbs on white keys, or on the key note when it's white or every note is black; triads use 4 beside the crossing across a third, 3 across a fourth; 7ths 1234 / 1432 from the thumb). `DEFAULT_FINGERINGS` (the ones I supplied) and any saved state `fingerings` ("RH : LH") override the rules; fingerings are no longer editable in the UI. `ArpForms` has two tabs (choice kept in `pianoPath.arpTab`): Forms, one line per form ("F♯ Minor  F♯ A C♯ F♯") to see the progression, and Fingering, the notes with RH/LH under them via `components/Fingering.tsx` (shared with the scales). Shown on Technique (key picker) and in Today's arpeggio block.
- `src/lib/plan.ts`: `todaysPlan()` builds the daily plan. `HIDDEN_BLOCKS` hides blocks from Today without deleting them (currently the étude). Scales and arpeggios each run their own rotation (`rotationKeys()`): today's key (one a day each) is the least-ticked key in circle-of-fifths order, so a key not ticked today comes first tomorrow. Ticks live in state `rot` (`n`: count per key per rotation; `day`: the latest day's ticks, folded into `n` on the next day's first tick). Each key row on Today has its own tick; the Scales row lists major + natural/harmonic/melodic relative minor with notes (`keyScales()` in `arpeggios.ts`, melodic shown ascending), each with standard one-octave RH/LH fingering aligned under the notes (`SCALE_FINGERINGS`, fixed, not editable), the Arpeggios row shows the 11 forms (hands separately for keys not yet solid).
- Logging is automatic: every tick on Today (block or key) rewrites that day's single `auto` log entry (`autoLog()` in `actions.ts`) with the items ticked and their count `n` (each key in a rotation block, plus each other block). Its `ts` is the date at 00:00 UTC, so all devices update the same entry through sync; if that ts was deleted, it moves to ts+1. There is no Log-this-session button; the Log tab form (date + note, required) is for practice outside the plan and counts as one item. The Log's streak, 14-day chart and stats count items (`itemCount()` in `Log.tsx`, which also counts old entries from their text).
- `src/lib/chords.ts`: diatonic triads and 7ths stacked from `keyScales()` notes (minor = harmonic minor's raised 7th only in V and vii°, so III stays major), `invert()`, standard chord fingerings, and two cadences per mode voiced by nearest voice leading from a chosen starting position (`voice()`, which any progression can use; `spell()`, `secondaryDominant()`, `secondaryDim7()` build V⁷/x and vii°⁷/x). `src/components/ChordView.tsx` shows them (numerals and names wrap before their quality suffix via `Wrap`, so "IVmaj7" / "C♯m(maj7)" fit seven columns on a phone instead of being cut off) (major/minor × triads/7ths/cadences × inversion), on Technique (key picker) and in Today's Chords block. Chords are a third rotation (`rot` key `chord`, one item a day via `chordRotation()` in `plan.ts`) over `CHORD_ITEMS` in `curriculum.ts`: 24 items, ids `"C:maj"` / `"C:min"`, in the order C major, A minor, G major, E minor, …; Today shows only that mode (`ChordView` `only` prop), Technique keeps the major/minor toggle. Old saved chord counts and ticks keyed by plain key (`"C"`) are split into both items in `normalize()`. The block id is `chord`.
- Chords in sheet music: a Letters/Staff toggle in `ChordView`. Staff draws hand-made SVG (`components/Staff.tsx`) with glyph outlines from the Bravura font (`src/lib/glyphs.ts`, SIL OFL, extracted once with opentype.js, so no font file or music library is loaded). `src/lib/notation.ts` works out the key signature, the accidentals to print (each chord has its own bar, so the minor's raised 7th always shows) and staff positions. Triads and 7ths go on one staff (treble for RH or bass for LH), rising by step and centred on the staff; cadences go on a grand staff, the right hand at the octave it's voiced in (`CadenceStep.pitches`) and the bass from the tonic (C3–B3) down to a fifth below. Chord names go above, numerals below. Rows wrap like systems when the chords don't fit the width (never below 0.85 scale), each starting with clef and key signature.
- Chord quiz (Study → Chords in a key: `ChordView` with `quiz`, always on the staff; Technique has no quiz): names and numerals show "?" until a chord is tapped (tap again hides it); triads and 7ths come in a shuffled order (never the plain rising one), cadences keep their order and their heading reads "Cadence 1/2" until all their chords are shown. "Show all", then "New order" (or "Hide again" for cadences). Quiz state isn't saved: it starts fresh when the key, mode, chord type, inversion or clef changes (`key` on `Grid` / `Cadences`).
- Study (`src/views/Study.tsx`, drills in `src/study/`): reading and harmony drills, only when opened (no Today block, nothing logged). `#study` lists `DRILLS` by group; `#study/<id>` opens one (the App's hash router passes the part after `/` as `sub`). See `PLAN.md` for the milestones. Key signatures (`study/KeySigs.tsx`): rounds of the 12 signatures, timed from the card appearing to the right answer, goal under 2 s; name the key (staff, clef treble/bass/both) or find the signature (count buttons); a right first answer moves on after 0.9 s, a miss waits for Next. `study/common.tsx` has `KeyPicker`, `shuffle`, `pick`.
- Study self-marking: state `study.miss` (outstanding misses per item id `"<drill>:<…>"`, +1 on a miss, −1 when right, capped at 3, removed at 0) and `study.days` (`[answered, right]` per day per drill, 60 days), written only through `recordAnswer()` in `actions.ts`. `src/lib/study.ts`: `weakItems()` (outstanding items of a drill, filtered to the current settings), `chooseItem()` (a weak item about a third of the time, never the one just shown), `todayCount()`; the drill list shows "n today · n to review". Key signatures record every right answer (first try or not) as `keys:<key>` and ask a missed key once more at the end of the round (as the other mode, not scored). Chord flashcards (`study/ChordCards.tsx`): one chord, any key (or one), major/minor/both, triads/7ths/both, on treble, bass, both hands (left hand the bass note, right hand the chord in a random close position) or mixed; Show answer gives the figured numeral (`figured()` in `chords.ts`: ⁶, ⁶₄, ⁷, ⁶₅, ⁴₃, ⁴₂) and slash name (`slashName()`), then Got it / Missed; item ids `cards:<key>:<mode>:<3|7>:<degree>:<inversion>`. `placeChord()` in `notation.ts` puts one chord on a staff in the octave with the fewest notes off the staff.
- Reading passages (`study/Reading.tsx`, generator `src/lib/passage.ts`): `makePassage(key, mode, level, meter)` builds 8 bars, one chord per bar: a 4-bar phrase ending on V, then one ending V–I, from fixed degree tables (`FIRST` / `SECOND`, the same degrees in minor; level 4 also uses `FIRST_SEC` / `SECOND_SEC` with V⁷/x, spelled by `spell()`); the V before the last I often takes its 7th from level 2. Melody: chord tones on strong beats near the previous one, then passing runs / neighbours / chord tones in between, spelled against each bar's chord (`chordScale()`: minor uses melodic minor's raised 6th and 7th over chords with the leading note); level 4 sometimes raises a note leading up a whole step. Left hand: 1 held root-position chord, 2 bass + chord (3/4 waltz, 4/4 bass–chord–fifth–chord), 3–4 eighths (4/4 Alberti, 3/4 root–5th–8ve–10th); the last bar is a held chord. Pitches are diatonic steps (octave × 7 + letter) plus accidental. `toAbc()` writes ABC with accidentals by printed-music rules (key signature, then what the bar changed on that line or space), beams on the beat, `%%barnumbers 1`, two or four bars per system (`perLine`, from the width), chord names as ABC chord symbols above and numerals as annotations below for bars that are shown. **abcjs** renders it (`responsive: "resize"`, `foregroundColor: currentColor`); it is imported dynamically so it's a separate ~510 kB chunk (`chunkSizeWarningLimit: 600` in `vite.config.ts`) fetched only on this page, then cached by the service worker. Bar chips under the score reveal each bar's numeral (and print it in the score).
- Harmony drills (`study/Harmony.tsx`, all on a grand staff via `voice()` + `cadenceOnStaff()`, whose bass sits from a 6th below the tonic to a whole step above it, tonic B2–A♯3): Diminished 7ths shows the three pitch sets with their four spellings each (vii°⁷ of every minor key), then flashcards `dim7:<key>:<inversion>` (no key signature by default, so the spelling gives the key away) with the resolution (bass: leading note → 1, 2 → 3, 4 → 3, ♭6 → 5) shown on reveal; Secondary dominants: tonic, then V⁷/x or vii°⁷/x in any inversion, then x (major targets ii–vi, minor III–VI), names hidden until Show answer, ids `sec:<key>:<mode>:<target>:<V|D>:<inversion>`; Cadence types: three chords ending authentic / plagal / half / deceptive, answered with buttons (auto-marked, `cad:<type>`; right first time moves on after 1.4 s).
- Analysis notes (`study/Analysis.tsx`): pick a piece (Keep up pieces as `keep:<title>`, then every stage's repertoire item by id), then sections with bars, key, harmony (Roman numerals, free text) and a note, in state `analysis` (synced; edits save on blur, through `addAnalysisRow` / `setAnalysisRow` / `deleteAnalysisRow` / `restoreAnalysisRow` in `actions.ts`). A new section starts after the last one's end bar, in its key. Focusing a harmony field shows a keypad of symbols a phone keyboard lacks (° ø ⁷ ⁶ ⁵ ⁴ ₅ ₄ ₃ ₂ ♯ ♭ / – →), inserted at the caret. Delete shows an Undo toast for 8 s. Path theory items with a matching drill link to it (`STUDY_LINKS` in `study/links.ts`).
- Practice is item based, not timed: Today is ticks only (no minutes, no bpm), and blocks have no minutes. Today has no progress ring or stage header (I sometimes leave items unticked on purpose so they come up again tomorrow); its heading is just the date. `settings.minutes` stays in saved state but is unused.
- Today layout: the date heading, then each block as its own card on the page (no outer card, no footnote), to keep the width on phones. When a rotation block has one key (the default), its content (`KeyContent`) sits right in the block and the block's tick is the key's tick; only with several keys does it show `KeyRows`, flat rows with dividers, each with its own tick. The chords and the 11 arpeggio forms are always shown (no Show/Hide link). Tapping a block's header (category + title, with a chevron) folds the whole block shut or opens it; the tick stays separate. Folded block ids are kept per device in `pianoPath.collapsed` until opened again. On phones (≤600px) a block's (and key row's) content below the title spans the full width instead of indenting past the tick (`.block-more`, `.key-row-more`).
- `src/lib/audio.ts`: Web Audio metronome sounds (`metroTick`: woodblock `click`, beep, wind-up with a bell on the first beat) and chime (the block timer was removed).
- `src/views/`: Today, Path, Technique, Study, Log. `src/components/`: Metronome, icons, small UI pieces. Routing is the URL hash (`#today`, `#path`, `#technique`, `#study`, `#study/<drill>`, `#log`).
- Styling: plain CSS in `src/styles.css` with design tokens in `:root`.
- **Theme**: System / Light / Dark per device (`src/lib/theme.ts`, localStorage "pianoPath.theme", nothing stored = System), chosen in settings (`components/ThemePicker.tsx`). It sets `<html data-theme="light|dark">`; an inline script in `index.html` does it before the first paint. Also a style per device, Classic / Bear (localStorage "pianoPath.style", `<html data-style="classic|bear">`, `StylePicker`): Bear redefines the surface / text tokens with Bear's greys (Knowledge Path's Graphite values, this app's accent kept); the theme-color metas take the style's background (`BARS` in theme.ts and the first-paint script). Dark tokens are `:root[data-theme="dark"]`, a dark-only rule is `:where(:root[data-theme="dark"]) .x { … }` (same specificity as `.x`). Never use `@media (prefers-color-scheme: dark)` in CSS.
- PWA: `public/manifest.webmanifest`, PNG icons in `public/icons/` (iOS needs the 180px PNG as apple-touch-icon), and `public/sw.js` (registered in production only). The service worker caches the page and the files it links on install, uses network first for the page and cache first for hashed assets, and never touches the GitHub API. If you add a file that must work offline and isn't linked from `index.html`, it is cached the first time it loads. On iOS the Home Screen app has its own storage, separate from Safari, so each install connects sync once.

## Rules for changes

- Design mobile-first (iPhone width ~390px), with tap targets of at least 40px, and check the iPad width too. Below 768px there is a bottom tab bar (five tabs); above it, a top segmented nav.
- Colours come only from the CSS tokens in `:root`, and both light and dark themes must stay readable.
- Audio (metronome) starts only from a user tap (iOS requirement). While it plays, the screen is kept on (`useWakeLock` in `src/lib/wakelock.ts`): a locked iPhone throttles the clicks.
- Run `npm run build` after edits; it must pass with no type errors.

## Deploy

GitHub Actions (`.github/workflows/deploy.yml`) builds and publishes to GitHub Pages on every push to `main`. Repo setting: Pages source = GitHub Actions. After a push, wait for the action, then reload on each device.
